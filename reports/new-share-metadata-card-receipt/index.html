Share metadata · 22 Oct 2026 · limited public trace

Can a new share use the corrected title, description and image?

Not established. The ordinary public page could not be fetched from the research environment. Its current metadata, image response and native platform card remain unobserved. A saved publication snapshot shows what was assembled earlier, not what a new share would show now.

ScopeThis check concerns one public research-report URL, the page-publication receipt. It is not a customer campaign-page test. A DNS failure in the research environment does not show that the page failed for readers.

How to close the question for one page

  1. Fetch the ordinary public URL. Record requested and final URL, redirects, status, UTC time, response headers, and the returned head and visible copy. Do not substitute an authoring preview or cache-busting URL.
  2. Fetch the exact selected image. Read the literal image metadata value, resolve it against the final page URL, then record the image response, MIME type, dimensions and bytes.
  3. With page-owner permission, inspect one native platform preview. Retain the displayed title, description, image and time for the exact ordinary URL. Compare those pixels and text with the intended share copy. Treat a forced recrawl as an active operation, not a passive check.
  4. Handle old posts separately. Preserve each permalink and decide whether a new post or visible correction is needed. A refreshed preview for a new post cannot recall prior exposure.

The Open Graph protocol defines basic title, type, image and URL properties and optional description; it does not prove that a platform fetched or displayed this page. LinkedIn sharing help describes use of oEmbed and/or Open Graph, and LinkedIn Post Inspector help says refreshed URL information affects new posts, not existing ones. No Post Inspector submission occurred in this check. The saved twitter:card=summary field alone does not establish an X card layout or precedence rule.

Tool choice and open evidence

For one page, use the manual sequence above. No metadata-checker project was selected, versioned, licensed, executed or assessed for network and data exposure. For repeated checks across many pages, first audit an exact tool version and whether it checks only HTML or also image responses and native platform results.

Still open: an ordinary public response from a working network vantage; current metadata and image response; an authorized native preview; intended share copy; and any existing-post record. Until those are retained, do not claim the corrected card is ready or that an old share has changed.
