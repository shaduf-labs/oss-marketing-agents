Campaign-page search visibility · 27 Oct 2026 · documentation review

Keep a campaign page public, retire it, or keep it private?

Choose the intended visitor state before choosing a search control. A URL that anyone can open, a URL absent from Google Search, and content that unauthenticated visitors cannot read are three different outcomes.

Evidence statusGoogle primary guidance was checked on 27 October 2026. No authorized page, Search Console property, server response, indexed result or removal request was inspected. The table is a decision and receipt plan, not a completed removal.

Google says a crawled noindex meta tag or header can remove a page from its results. A robots.txt disallow can prevent the crawler seeing that rule while a linked URL can still appear without crawled content. Do not use robots disallow as a substitute for, or layer it over, a crawlable noindex when the aim is to hide the result. Google: noindex · Google: robots.txt · Google: remove a page

Timing changes the sequence

  1. Already public and indexed: approve the intended lasting state and inventory exact result URLs, including case, query, host, protocol, redirect and asset variants. Apply the matching site-side control immediately. For confidential content, protect the content before waiting for a Search result change.
  2. Urgent Google suppression, when warranted: an owner of the relevant Search Console property can request a Temporary Removal for an exact URL or appropriately scoped prefix. Track request scope and status. Google describes processing as usually within a day, not guaranteed, and the block as lasting about six months; permanent site-side control remains necessary. It removes a Google result, not content from the internet. Search Console Removals help
  3. Not yet public: publish the crawlable noindex response from the start if the page may remain public; keep an embargoed offer and assets behind access control or off the public site; do not create a public 200 for a page that should not exist. A Removals request is not a pre-publication privacy gate.

A canonical link expresses a preferred duplicate URL, not a de-indexing or confidentiality command. Removing a URL from a sitemap does not revoke a live page. URL Inspection’s live test checks current potential indexability, not whether Google’s stored result has been removed; “Request indexing” is a crawl request, not a guaranteed outcome. Google: canonical methods · Google: sitemaps · Google: URL Inspection

One exact-URL receipt

Use this record only for a page the operator is authorized to inspect. Keep the current site response and Google’s later state separate.

Stop at the supported claim. A verified response supports “this checked variant now serves noindex/404/410 or protects the offer.” It does not mean Google has caught up. If the last crawl predates the change, variants remain exposed, property access is unavailable or a request is merely submitted, record search state as pending or unknown and recheck. Even a Google result change says nothing about other search engines, copied pages, social cards or existing posts. URL Inspection · Removals help

Evidence limits and related checks

No page, Googlebot fetch, indexed state, Search Console request, removal, asset or social-card state was observed for this decision. No local fixture was built: syntax alone would not show whether Googlebot can reach an authorized URL or when Google updates its index. Before a real case, identify the approved intent, exact URL variants, current indexing state, CMS/server operator and Search Console property owner.

The page-correction receipt separates approval, deployment, public response and indexed copy. The share-card report keeps a native platform card separate from saved metadata. Neither is evidence that today’s three controls have been applied.
