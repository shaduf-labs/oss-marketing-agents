Harness-library dossier · verified 25 Sep 2026

Marketing Agent OS: portable skills, not a marketing application.

Marketing Agent OS provides marketing-oriented skills and related materials for an approved host harness. The library does not establish the host’s permissions, credentials, network access, approvals, logs, or recovery controls.

Current boundaryA 25 September repository audit found Apache-2.0 declared for the wrapper/normalized layer, while retained upstream snapshots have component-level provenance and licence records. Exact retained-file provenance was not independently verified.

What the checked material supports

Selected-skill projection.
Architecture describes selected skills being projected into a target harness directory, with tracked upstream snapshots excluded. The project documents staging and atomic replacement; exact copied files, collision behavior, backups, and rollback were not verified here.

Policy is not an enforcement system.
SECURITY says external and persistent actions need authorization and optional connectors inherit host/provider security. The audit did not establish a built-in sandbox, approval engine, credential vault, network allowlist, or runtime audit log.

The README’s count of 236 installable skills conflicts with the architecture/compatibility count of 235 portable skills. Treat both as project claims until the current catalogue and intended output are reviewed.

What adoption requires

  • Choose and approve the host harness, its tool permissions, filesystem scope, network access, credentials, logs, retention, and recovery.
  • Review the selected skill directories and installer source before a write; use a small selected set rather than bulk installation.
  • Verify retained notices and provenance for the particular material you plan to use.
  • Use no client data, secrets, configured connectors, or external actions in the first evaluation.

Conditional choice

Choose it whenYou already operate a permissioned coding-agent harness and want local, reviewable marketing-planning instructions. Do not choose it as a hosted app, CRM, sender, scheduler, credential store, or autonomous publishing system.

For a first evaluation, use an empty non-client repository and fictional facts. Review only a local planning draft and its file diff, then clean up. Do not send, post, spend, mutate accounts, use production credentials, expose webhooks, or schedule work.

Evidence and limits

Visible history and a private vulnerability-reporting route are limited maintenance/process signals. README claims about tests, CI, and compatibility were not reproduced. See the permanent provenance and host-harness boundary audit for sources, explicit unknowns, and the bounded evaluation plan.
