Public, retired, or private campaign page?

The 27 October decision table chooses crawlable noindex, a real 404/410, or access control by intended visitor state. Its exact-URL receipt keeps the current public response apart from a later Google indexed result. Documentation review only; no site or Search Console state was observed.

Does one-click unsubscribe point to the right list?

The 26 October offline header check accepted two valid A/B messages and rejected all nine planted unsafe headers in a fictional parser fixture. Compare a captured final message with an independently approved list mapping before sending. The test did not validate DKIM, run a POST, exercise Listmonk or prove endpoint, mailbox, consent or delivery behavior.

Reconcile two newsletters before a migration?

The 24 October local no-send fixture matched all 18 invented newsletter slots and rejected four planted unsafe target proposals. An evidence token is only a fictional locator, not permission proof. This did not exercise Listmonk or a real import; the 16 October source audit supplies the separate tagged-code boundary.

Check a planned campaign link before sending

The 23 October offline fixture compared parsed destination and UTM values with one fictional approval contract. All 17 expected outcomes matched; the checker caught absent, empty, duplicated and conflicting tags, wrong destinations, embedded credentials and fragments. This is pre-send string QA, not a live-link, sender or analytics test.

Will a new share show corrected metadata?

The 22 October share-card trace did not reach an ordinary HTTP response. The saved assembled page has metadata fields but does not establish current title, description, image or native platform display. Check the public page, selected image and an authorized native preview in that order; handle existing posts separately.

Did approved copy reach the public URL?

21 October page-publication receipt separates approved, deployed, public and indexed states. Start with a manual normal-URL response: final URL, status, exact approved marker, canonical/robots, cache headers, UTC time and variant. The three receipts are fictional; no customer page was checked.

Which page should be refreshed?

Read the 20 October one-page diagnosis. A fictional three-page card separates refresh, technical/provider diagnosis and wait/unknown. It uses exact Search Console page/query filters and two complete 14-day PT windows, then manual URL and content checks. SiteOne is conditional; no live site or SEO effect was measured.

Search Console and a rank tracker disagree?

Read the 19 October Search Console–first decision. Match the query, canonical page, country, device, Web search type and complete dates before reading average position. SerpBear v3.1.0 can add a fixed provider snapshot only with the matched result URL, checked depth and failure status. A fictional triage card shows when to investigate indexing, inspect content, wait or retain an unknown. No live rank was measured.

One email before a real send?

The 18 October pre-send decision compares a verified existing preview/test path with an isolated Mailpit v1.31.5 SMTP capture. No message was sent or captured. A local receipt would establish only what reached that sink, not provider acceptance, recipient display or permission to send.

One welcome and an occasional newsletter?

Start with the 4 October small-list welcome decision contract. It separates DOI request, one immediate message, ongoing campaigns and delayed sequences, then tests the existing-sender option against consent, approval, suppression, attempts, provider outcomes and recovery. For a new one-message system, phpList is a conditional private-evaluation route, Keila is a form-centered alternative, and Listmonk needs a reviewed external/manual trigger and ledger. None is send-ready or added to the four-layer shortlist. If you already operate a Ghost publication site, its native one-message welcome is a conditional off-ramp documented on 5 October, not a send-vetted choice. Ghost's opt-in timed-sequence beta requires a separate audit. Earlier dated audits remain below.

Client sign-off before a social post?

The 7 October Postiz v2.25.0 report distinguishes a draft preview/comment conversation from a required approval gate. Current docs do not show an enforced two-person sign-off, and a no-channel in-app draft is not established. Start with offline fictional copy; a later Postiz trial needs a permissioned test channel and private deployment. Postiz is not a vetted shortlist choice.

Newsletter campaign measurement?

The 8 October Umami v3.4.0 report separates sender delivery, tagged site views, a site-emitted signup signal and verified account records. It documents the page-view UTM query and model-based attribution but no end-to-end runtime result. A private synthetic pilot is the next step; Umami alone cannot verify an account or campaign lift. This is an investigation, not a shortlist addition.

Another self-hosted measurement route

The 9 October Plausible CE v3.2.1 audit finds tagged-source support for UTM-bearing pageviews and a separately instrumented signup event. First-party docs describe Campaigns and goal rates, but no CE dashboard was observed. CE is a conditional synthetic-pilot choice if the team can operate the app, PostgreSQL and ClickHouse, and verify the v3.2.1 security patch and deployment exposure. Unlike a verified account record, its event remains a browser-side receipt. This is not a four-layer shortlist addition.

Five-page site promotion?

The 10 October SiteOne Crawler v2.5.1 report puts manual review first. A crawl is conditional on owner permission and an external exact host/path guard; the tool's URL-list and noindex-alert limits make a crawler score unsafe as the decision itself. This was a source-only audit, not a runtime test or shortlist addition.

One campaign link?

Use a direct approved HTTPS URL with UTMs unless shortness or controlled retargeting justifies another service. The 11 October YOURLS 1.10.6 source audit explains core create, edit, 301 redirect and click-count behavior, with an external approval/rollback ledger. Clicks are not arrivals or signups; no runtime behavior was observed.

AI-written campaign copy before sign-off?

Start with an approved-facts card and a human checklist. Repeated stable URL, phrase and length rules may justify a tiny script; a matrix across many drafts, prompts or models may justify promptfoo. The 12 October promptfoo 0.124.1 source audit keeps claim review and exact-version publication approval with people. No eval or campaign approval was observed.

Does one campaign image need a DAM?

Use a controlled folder, versioned register and a three-placement ledger first. The 13 October ResourceSpace decision compares a small script and a self-hosted DAM, and distinguishes the expiry-field warning from plugin/cron state changes. No immutable 11.0 artifact or install was inspected; external placements require separate action.

One offer, two languages, three placements?

Start with the 14 October localized-offer release-control report. Its bilingual register gives each landing, email and social variant an exact version, language and campaign-fact review, destination owner and queue/live/sent receipt. The fictional v1 email stop is unconfirmed and remains held. Weblate 2026.10.1 is a conditional repository-string route, not a channel approval or release system; this was release/documentation reading only.

Planned versus observed across three placements?

The 15 October campaign calendar and receipt-ledger audit starts with a shared calendar plus versioned destination receipts. Its fictional landing delay, unknown email cancellation and already-public social post show why a planned slot or completed task cannot prove release. Vikunja v2.7.0 can coordinate owners and reminders if handoffs repeat; it does not replace channel checks. This is a source audit, not a live campaign or installed-board test.

Moving two newsletters without reviving opt-outs?

Read the 16 October source audit before exporting contacts. Check whether the current service can retain A/B-specific preferences, global suppression and permission history. Listmonk v6.2.0 tagged paths make disabled and single-opt-in unconfirmed unsafe generic holding labels. Keep unknowns outside sendable lists, investigate overwrite collisions and read back every A/B and global state after late-event replay. The nine-contact example is fictional; no migration or send was tested.

Can a form inquiry be reconciled to a CRM contact?

Read the 17 October form-to-contact audit. Start with the existing form and CRM: for every accepted submission, preserve an event ID, source and stated contact preference, destination CRM ID or owned exception. Mautic 7.2.1 documents form submissions and associated contact IDs, but its generic POST and plugin actions do not establish a durable, idempotent CRM handoff. No exact-build, connector or CRM test was run; current 7.2 support status needs maintainer confirmation.
